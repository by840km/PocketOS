# Обновление 0.3 — запуск и интерфейс

Дата проверки: 2026-11-24 (Asia/Krasnoyarsk).

## Изменения

- Нативный WPF-загрузчик: полноэкранный градиент, индикатор, моноширинный журнал этапов, отмена и совместимый повторный запуск. Используется системный .NET Framework Windows, установка отдельного клиента не требуется.
- Rust-core принимает этапы из виртуального последовательного порта, привязанного только к localhost. GNOME readiness-service проверяет владение org.gnome.Shell в пользовательском D-Bus, затем сообщает READY.
- Переключение основано на сообщении гостя; индикатор не изображает фиктивный процент готовности. При ошибке/тайм-ауте предусмотрены сообщение и ограниченный fallback.
- Убран ранний SDL -full-screen. GL-контекст остаётся активным в окне под непрозрачным загрузчиком; после готовности окно становится безрамочным. Точная единственная причина исходного симптома 0.2 отдельно не изолирована.
- Исправлен разбор READY после приглашения `pocketos login:` в той же строке serial. Добавлен регрессионный сценарий фрагментированного сообщения с таким префиксом.
- Принятый TCP stream явно переводится в blocking mode с read timeout, исключая busy-spin Windows socket. Native window operations асинхронны; проверка USB выполняется до них.
- WPF-parent и Rust-core используют kill-on-job-close для своих дочерних процессов. PE removable flag применяется к обоим EXE.

## Проверено

13 unit-тестов пройдено; ignored helper используется только как дочерний процесс тестов.

Оформление экспортировано самим WPF RenderTargetBitmap и визуально проверено (evidence/loader-preview.png). Системный Windows capture helper в этой сессии недоступен.

Живой запуск с D: в VirGL-профиле дал START 19:45:17Z, KERNEL 19:45:25Z, ROOT 19:45:33Z, DESKTOP_START 19:45:36Z, READY 19:45:43Z. Evidence: v03-live-v3.log. Переход к рабочему столу пользователь подтвердил текстом. Это результат одного запуска, не гарантия времени на других ПК.

Базовый Linux-диск не перезаписывался. Сеанс остаётся read-only base + volatile RAM overlay. Облако и постоянный профиль не реализованы.

Новый графический слой требует отдельной проверки физического извлечения USB вместе с пользователем; проверки native job/media supervisor пройдены автоматически. Обычный GUI-сеанс сейчас открыт для пользователя.


## Физический тест USB — завершён

Пользователь подтвердил: после появления рабочего стола извлёк флешку, PocketOS закрылась и вернулась Windows. Контрольная проверка показала: процессов PocketOS.exe, pocketos-core.exe и qemu-system-x86_64.exe не осталось. Во время записи финального отчёта том D: снова доступен; сам момент физического отключения подтверждён пользователем.

Результат относится к установленной версии 0.3 с новым графическим загрузчиком и к этому ПК. Рабочая сборка 0.3 и итоговый отчёт сохранены на USB и в исходниках.
