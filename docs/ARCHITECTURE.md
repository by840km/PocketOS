# Текущее уточнение архитектуры: RAM root

В проверенном прототипе запуск выполняется напрямую с внешними vmlinuz/initrd.img. Базовый QCOW2 открыт readonly=on. Собственный init монтирует ext4 нижним слоем только для чтения; верхний слой OverlayFS — tmpfs с лимитом 1 GiB. Монтирование EFI и growfs не нужны в этом режиме. Ниже сохранён исходный план, его изменяемый диск и постоянный профиль пока НЕ реализованы.

В этом прототипе весь сеанс временный: файлы, настройки и токены не переживают выход. Облако ещё не подключено. Следующий этап хранения — отдельный зашифрованный том профиля и очередь облачной отправки, без перевода всей ОС обратно на частые USB-записи.

Код загрузки: system/ramroot/init и build.py. Guest kernel 6.12.118 соответствует модулям установленной системы. В initramfs используется ранний userspace Debian installer, но его /init заменён нашим: установщик не запускается.

# Архитектура v0.1

## Граница Windows / Linux

Windows → Rust launcher → portable QEMU → установленный Debian → KWin + PocketOS Shell.
Внутри гостя: Shell → cloud-agent → rclone/FUSE → Nextcloud WebDAV через TLS.

Windows-компоненты не монтируют облако и не получают облачные токены. QEMU использует только виртуальный диск; физические диски Windows не передаются гостю. Сеть первой версии — user-mode NAT без входящих пробросов портов. Не устанавливаем службы, драйверы или автозапуск в Windows.

## Формат переносной папки

```
PocketOS.exe
qemu/                   # exe, DLL, firmware/share; проверенные версии
system/pocketos.qcow2    # установленный гостевой диск, BIOS boot
docs/
```

Первая версия использует один изменяемый гостевой диск. Внутри него планируются системный раздел и зашифрованный раздел данных для профиля, токенов и VFS-кэша. Разделение на неизменяемый базовый образ и обновляемые слои — последующий этап; нельзя переключать базу под существующим QCOW2 overlay без миграции.

exFAT находится только снаружи, внутри гостя — Linux FS. Нужно проверить sparse-файлы, нехватку места и восстановление QCOW2 на реальной флешке. Вся библиотека облака на USB не скачивается, но открытые файлы и неподтверждённые записи используют место в кэше. 2 GiB — целевой мягкий бюджет кэша, не гарантия верхнего предела: грязные и открытые файлы нельзя просто удалить.

## Shell

Форк KDE Plasma, прямые изменения GJS/CSS/C, без расширения. KWin сначала без изменений. Версии Shell/KWin берутся из одного набора Debian и фиксируются до разработки интерфейса. Собственные окна настроек — отдельное приложение; Shell не меняет оформление всех GTK/Qt-приложений.

Пока upstream-код НЕ скопирован и fork НЕ создан. В desktop/ описан порядок подготовки. Результат внедряется своим deb-пакетом и собирается в гостевой образ.

## Cloud-agent

Служба внутри гостя управляет жизненным циклом rclone, получает свежую телеметрию и публикует состояние через пользовательскую D-Bus-службу (контракт пока проектируется). Shell не читает пароли. Управляющий интерфейс rclone доступен только локально с аутентификацией, не через сетевой проброс QEMU.

Не писать второй независимый uploader поверх VFS-кэша rclone. Не удалять кэш при старте или ошибке сети. Подключение облака не означает, что файлы сохранены. Обрыв телеметрии немедленно переводит индикатор в Unknown.

Пока реализован только чистый reducer состояний; нет адаптера rclone, постоянного журнала, D-Bus и шифрования. Даже Synced у reducer не является разрешением выключить ОС: сначала нужно прекратить новые записи, закрыть приложения, проверить очередь и активные операции, размонтировать облако и завершить гостя.

rclone mount сам по себе не гарантирует защиту от конкурентной правки. До реализации проверок версий — один активный писатель, без обещания автоматического слияния. Облачные изменения видны с задержкой обновления метаданных. Офлайн открываются только уже кэшированные данные.

## Завершение

Running → запрос завершения → сохранение приложений → запрет новых записей → ожидание подтверждённых загрузок → unmount → выключение гостя → выход QEMU.
При ошибке оставаться в состоянии ожидания; отдельный явный выход с неподтверждёнными данными сохраняет кэш и предупреждает о последствиях. Не убивать QEMU как обычный способ завершения. Закрытие окна QEMU считается потенциально аварийным.

## Безопасность

Шифрование данных и токенов ещё не реализовано. Не добавлять реальные ключи в репозиторий или образ для публикации. Компьютер-хост контролирует виртуальную машину; шифрование флешки не защищает открытый сеанс от скомпрометированного Windows. Обновления бинарников требуют подписей/проверок целостности перед публичным релизом.
